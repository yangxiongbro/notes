# Kafka

## Spring Boot 集成



在 Spring Boot 中消费 Kafka，主要通过 **`spring-kafka`** 依赖和 **`@KafkaListener`** 注解实现。下面是一套完整的实践指南。

---

### 一、添加依赖

```xml
<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>
```

Spring Boot 会自动配置 `KafkaTemplate`、`ConsumerFactory`、`KafkaListenerContainerFactory` 等。

---

### 二、基础配置（application.yml）

```yaml
spring:
  kafka:
    bootstrap-servers: localhost:9092
    consumer:
      group-id: my-group
      auto-offset-reset: earliest          # 无 offset 时从最早开始
      enable-auto-commit: false            # 建议手动提交
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      max-poll-records: 500                # 一次拉取最大条数
      properties:
        session.timeout.ms: 10000
        max.poll.interval.ms: 300000
    listener:
      ack-mode: manual_immediate           # 手动立即提交
      concurrency: 3                       # 并发消费者数，不超过分区数
```

---

### 三、基础消费者示例

```java
@Component
public class OrderConsumer {

    @KafkaListener(topics = "orders", groupId = "my-group")
    public void consume(String message) {
        System.out.println("收到消息：" + message);
    }
}
```

如果需要更细粒度控制，可以接收 `ConsumerRecord`：

```java
@KafkaListener(topics = "orders", groupId = "my-group")
public void consume(ConsumerRecord<String, String> record) {
    System.out.println("topic=" + record.topic() 
        + ", partition=" + record.partition()
        + ", offset=" + record.offset()
        + ", key=" + record.key()
        + ", value=" + record.value());
}
```

---

### 四、手动提交 Offset

配置 `enable-auto-commit: false` 和 `ack-mode: manual_immediate`，然后在监听方法中注入 `Acknowledgment`：

```java
@KafkaListener(topics = "orders", groupId = "my-group")
public void consume(String message, Acknowledgment ack) {
    try {
        // 业务处理
        process(message);
        // 处理成功，手动提交
        ack.acknowledge();
    } catch (Exception e) {
        // 处理失败，不提交，等待重试或进入死信
        log.error("消费失败", e);
    }
}
```

**注意**：`ack-mode` 常用值：

- `RECORD`：每条记录处理完提交一次（默认）
- `BATCH`：一批处理完提交一次
- `MANUAL` / `MANUAL_IMMEDIATE`：手动调用 `ack.acknowledge()` 提交

---

### 五、批量消费

配置 `batch-listener: true` 和 `max-poll-records`，监听方法接收 `List`：

```yaml
spring:
  kafka:
    listener:
      type: batch
      ack-mode: manual_immediate
```

```java
@KafkaListener(topics = "orders", groupId = "my-group")
public void consumeBatch(List<String> messages, Acknowledgment ack) {
    for (String msg : messages) {
        process(msg);
    }
    ack.acknowledge();
}
```

---

### 六、JSON 反序列化

配置消费者 value 反序列化为 JSON：

```yaml
spring:
  kafka:
    consumer:
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      properties:
        spring.json.trusted.packages: com.example.dto
        spring.json.value.default.type: com.example.dto.Order
```

监听方法直接接收对象：

```java
@KafkaListener(topics = "orders", groupId = "my-group")
public void consume(Order order) {
    System.out.println(order);
}
```

---

### 七、错误处理与重试

#### 1. 默认重试

```yaml
spring:
  kafka:
    listener:
      retry:
        max-attempts: 3
        backoff:
          interval: 1000
          multiplier: 2
```

#### 2. 自定义错误处理器

```java
@Bean
public DefaultErrorHandler errorHandler(KafkaTemplate<String, String> template) {
    DeadLetterPublishingRecoverer recoverer = 
        new DeadLetterPublishingRecoverer(template);
    return new DefaultErrorHandler(recoverer, new FixedBackOff(1000L, 3));
}
```

消费失败超过重试次数后，消息会发送到死信 Topic（默认 `原topic.DLT`）。

#### 3. 幂等消费

Kafka 只保证 **至少一次** 投递，重复消费无法完全避免。业务层需保证幂等：

- 唯一业务 ID + 数据库唯一索引
- Redis `setIfAbsent` 去重
- 状态机控制流转

---

### 八、并发消费

```yaml
spring:
  kafka:
    listener:
      concurrency: 3   # 启动 3 个消费者线程
```

**并发数不能超过分区数**，否则多出的线程空闲。增加并发需先增加 Topic 分区数。

---

### 九、常见问题

| 问题           | 原因                   | 解决                                              |
| -------------- | ---------------------- | ------------------------------------------------- |
| 重复消费       | 自动提交 offset 前失败 | 手动提交 + 幂等                                   |
| 消息丢失       | 自动提交后业务失败     | 关闭自动提交，处理完再提交                        |
| 消费积压       | 消费者处理慢           | 增加分区和并发、优化业务、批量消费                |
| 反序列化失败   | 类型不匹配             | 配置正确的 Deserializer 和 trusted packages       |
| Rebalance 频繁 | 心跳超时或处理超时     | 调整 `session.timeout.ms`、`max.poll.interval.ms` |

---

### 十、完整示例

```java
@Configuration
public class KafkaConfig {

    @Bean
    public ConcurrentKafkaListenerContainerFactory<String, String> kafkaListenerContainerFactory(
            ConsumerFactory<String, String> consumerFactory) {
        ConcurrentKafkaListenerContainerFactory<String, String> factory =
                new ConcurrentKafkaListenerContainerFactory<>();
        factory.setConsumerFactory(consumerFactory);
        factory.setConcurrency(3);
        factory.getContainerProperties().setAckMode(ContainerProperties.AckMode.MANUAL_IMMEDIATE);
        factory.setCommonErrorHandler(new DefaultErrorHandler(new FixedBackOff(1000L, 3)));
        return factory;
    }
}
```

```java
@Component
public class OrderConsumer {

    @KafkaListener(topics = "orders", groupId = "my-group")
    public void consume(ConsumerRecord<String, String> record, Acknowledgment ack) {
        try {
            // 幂等业务处理
            process(record.value());
            ack.acknowledge();
        } catch (Exception e) {
            log.error("消费失败，offset={}", record.offset(), e);
            // 不提交，等待重试或进入死信
        }
    }
}
```

---

**一句话总结**：Spring Boot 消费 Kafka 用 `@KafkaListener` + `spring-kafka`，生产环境建议 **手动提交 offset + 并发消费 + 错误重试 + 死信队列 + 业务幂等**，保证不丢不重。



## Kafka+入库

为了将“Spring Boot + Kafka + MyBatis-Plus + 达梦”这条数据链路的性能压榨到极致，我们需要从**Kafka消费端、应用处理层、MyBatis-Plus持久层、达梦数据库配置**四个维度进行全面优化。以下是详细的优化操作清单：

### 📥 一、Kafka 消费端优化

1.  **开启批量消费模式**：在 `application.yml` 中设置 `spring.kafka.listener.type=batch`，或者自定义 `ConcurrentKafkaListenerContainerFactory` 时调用 `factory.setBatchListener(true)`。这能让消费者一次性拉取多条消息，大幅减少网络往返次数。
2.  **设置合理的单次拉取数量**：调整 `max.poll.records` 参数（建议 500~1000 或更高，视单条消息处理耗时而定）。增加该值能提高吞吐量，但需确保这批数据能在 `max.poll.interval.ms` 超时前处理完，否则会触发 Rebalance。
3.  **调优拉取策略参数**：增大 `fetch.min.bytes`（如 1MB），并配合调整 `fetch.max.wait.ms`（如 500ms）。这会让 Broker 攒够足够的数据再返回，有效减少消费者频繁拉取的开销，适合高吞吐场景。
4.  **合理设置并发消费者数量**：通过 `spring.kafka.listener.concurrency` 设置并发线程数。**关键原则：并发数应小于等于 Topic 的分区数**，多余线程会空闲。通常建议设置在 10~15 之间，过高可能因上下文切换降低效率。
5.  **手动提交 Offset**：关闭自动提交（`enable.auto.commit=false`），采用批量处理成功后手动 `ack` 的方式（设置 `ack-mode: manual_immediate`），确保消息不丢失。

### ⚙️ 二、应用处理层（Spring Boot）优化

6.  **使用自定义线程池异步处理**：在 `@KafkaListener` 接收消息后，将耗时的数据库入库操作提交给独立的线程池执行，实现消息接收与数据持久化的解耦，避免阻塞 Kafka 拉取线程。
7.  **配置线程池动态扩缩容**：根据 Kafka 消费积压情况（Lag），动态调整处理线程池的核心线程数和最大线程数，做到资源弹性利用。

### 📦 三、MyBatis-Plus 持久层优化

8.  **启用 `ExecutorType.BATCH`**：在获取 `SqlSession` 或配置 `SqlSessionFactory` 时，将默认执行器类型设置为 `BATCH`。MyBatis 会通过 JDBC 的 `addBatch()` 和 `executeBatch()` 机制，将多条 SQL 攒批发送，极大减少与数据库的交互次数。
9.  **配置忽略空值判断**：MyBatis-Plus 的 `saveBatch` 在拼接 SQL 时默认会逐字段判断是否为空，这在海量数据下会产生巨大的反射和判断开销。在全局配置中设置 `insert-strategy: not_empty`，忽略空值字段的判断，可显著提升插入速度。
10. **关闭主键回填（`useGeneratedKeys`）**：如果达梦表使用 `IDENTITY` 自增主键，在批量插入时开启主键回填可能导致性能严重下降甚至报错。建议在批量插入场景下**禁用主键返回**，绕过驱动缺陷。
11. **升级达梦 JDBC 驱动**：务必使用最新版达梦驱动（如 `DmJdbcDriver18` 8.1.2.123+ 版本）。旧版本驱动在批量处理上存在缺陷，升级后能大幅改善 `batchUpdate` 的性能。
12. **谨慎对待 `rewriteBatchedStatements`**：达梦**并不支持** MySQL 的 `rewriteBatchedStatements=true` 参数。强行添加该参数可能无效甚至引发异常，请从连接串中移除。

### 🗄️ 四、达梦数据库调优

13. **修改 `dm.ini` 开启批量参数优化**：将达梦参数 `BATCH_PARAM_OPT` 设置为 **1**（默认为0）。开启后，数据库内部会针对批量绑定的 SQL 进行优化，避免逐行处理，显著提升批量插入效率（需重启数据库生效）。
14. **开启二级索引快速插入标志**：将 `INDEX_FINS_FLAG` 设置为 **1**。这会让数据库先缓存索引变更，排序整理后再一次性批量写入索引页，有效减少 B+ 树索引的随机 I/O 和页分裂，降低索引维护开销。
15. **增大日志缓冲区 `LOG_BUFFER`**：适当调大 `LOG_BUFFER` 参数，减少事务日志频繁刷盘的 I/O 次数，提升整体写入吞吐。
16. **合理设置批量大小与手动提交**：单批次数据量建议在 **500 到 1000 条**之间（过大可能导致 SQL 解析变慢）。关闭自动提交（`SET AUTOCOMMIT OFF`），在一批数据处理完成后统一 `COMMIT`，减少事务日志刷盘频率。
17. **权衡索引维护**：如果是一次性大批量历史数据导入，可考虑在插入前**禁用非主键索引**，插入完成后再重建索引，避免插入过程中频繁维护索引的开销。

### 💎 总结

最大化这条数据链路性能的核心，在于将“**逐条处理**”全面转变为“**批量处理**”与“**异步解耦**”。你可以对照上述清单，从 Kafka 端攒批拉取，到应用层异步消费，再到 MyBatis-Plus 攒批发送，最后到达梦数据库开启批量参数，逐层消除瓶颈。
